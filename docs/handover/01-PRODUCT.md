# 01. Продукт и изначальные инструкции

## Что это

**kleekTo** — SaaS CRM для агентств недвижимости. Рынок — Грузия. Многопользовательский,
многоарендный (каждое агентство — отдельная компания со своими командами).

Продукт состоит из двух частей:

- **веб-приложение** (Next.js) — база объектов, воронка, доска, лента, чат, аналитика;
- **расширение Chrome (MV3)** — работает на сайтах объявлений `ss.ge` и `myhome.ge`,
  переносит объявление в базу и заполняет форму размещения.

Без расширения главный цикл не замыкается: именно оно читает страницу объявления
и отправляет объект в базу.

## Рабочий цикл агента — то, ради чего всё написано

```
лента рекомендаций → открыл объявление → раскрыл телефон → позвонил
   → «Согласен» → объект в базе, статус «В базе»
   → «Заполнить» на форме площадки → разместил сам → «Принято в работу»
```

Агент звонит **только собственникам**: им нужна помощь с продажей, и за неё
платят комиссию. Объявление, поданное другим агентством, бесполезно — там уже
есть свой агент.

Кроме «Согласен» в меню расширения ещё три исхода разговора:

| Исход | Что делает |
|---|---|
| **Согласен** | Создаёт объект, закрепляет за агентом, убирает объявление из ленты компании |
| **Отказ / не звонить** | Объект НЕ создаёт. Помечает объявление; у других команд оно остаётся |
| **Недозвон** | Объект НЕ создаёт. Объявление вернётся в ленту примерно через сутки |
| **Перезвонить через N дней** | Объект НЕ создаёт. Возврат в ленту к нужной дате |

Отдельная галочка «собственник просил больше не звонить» убирает объявление
у всего агентства — это область компании, а не команды.

**Приоритет №1 всегда:** скорость и надёжность главного цикла. Лента, индекс
и аналитика уступают ему всегда.

## Изначальные инструкции: откуда взялись правила

Проект вёлся по двум документам, написанным до кода:

1. **`docs/spec/MASTER_PRODUCT_SPECIFICATION.md`** (2000 строк) — исходная
   спецификация продукта. **Не редактируется.** Написана раньше всего
   остального и не знает ни о публикации, ни о согласии, ни о ленте.
2. **`docs/MASTER_PROMPT.md`** (1354 строки, версия 2.2) — рабочий свод:
   правила, фазы, гейты, обязательный дизайн импорта, дедупликации,
   расширения и публикации.

**Приоритет при расхождении:** решения владельца → мастер-промпт →
спецификация → дизайн-документ.

Ключевое расхождение, которое надо знать сразу: черновая воронка из 10 статусов
в спецификации **устарела**. Действует набор из пяти, промпт §5Б.4. Подробнее —
в `05-DELTA.md`.

## Девятнадцать правил, которые нельзя нарушать

Это не стилистика. Каждое правило закрывает конкретный способ испортить данные
или нарваться на блокировку площадкой. Полный текст — в корневом `CLAUDE.md`.

0. **Объект появляется только по «Согласен».** Ни лента, ни индекс, ни фоновый
   процесс `Property` не создают. Исключения — ручное создание и миграция, оба
   помечаются полем `origin`.
1. **Маркируй уровни знания:** `[CONFIRMED]` / `[DERIVED]` / `[RECOMMENDED]` /
   `[OPEN]`. Рекомендация — не требование.
2. **Не выдумывай** DOM площадок, состав форм размещения, external ID,
   доступность телефонов, ToS, внешние API. Нет проверенных данных → запроси
   фикстуры и остановись.
3. **Гейты:** фаза заканчивается отчётом и стопом. Следующая — по команде `GO PHASE N`.
4. **«Готово» = запущены** `typecheck`, `lint`, `test`, `build`, вывод в отчёте.
5. **`companyId` — только из authenticated context.** Никогда из тела запроса.
   У каждого endpoint есть негативный тест на чужую компанию.
6. **Права — на сервере.** Фронтенд только прячет кнопки.
7. **Никаких заглушек**, mock-данных в production-путях, `any`, пустых `catch`.
8. **Секреты — только в `.env`**, `.env.example` держи актуальным.
9. **Применённые миграции не редактируются.**
10. **PII** (телефоны, имена, фото собственников) не логируются и не попадают
    в фикстуры в исходном виде.
11. **Правило раскрытого телефона.** Агент сам нажимает «показать телефон» —
    расширение читает уже раскрытый DOM. Оно **никогда** не имитирует этот клик,
    не дёргает внутренние endpoint'ы сайта и не импортирует объект без телефона
    молча. Когда номер со страницы не читается, агент вправе **вписать его
    руками** — правило про то, что номер сообщает человек, а не программа
    (`ADR-0012`).
12. **Правило «публикует человек».** Расширение заполняет форму размещения,
    но никогда не отправляет её, не ставит галочку согласия, не решает капчу,
    не работает в фоне и не поднимает объявления.
13. **Контакты собственника не уходят на площадку.** Черновик публикации
    собирается на сервере по белому списку полей и не содержит `OwnerContact`;
    описание очищается от телефонов. Проверяется тестом.
14. **Частичное заполнение — штатный режим.** Заполняем поля, для которых есть
    данные; остальные перечисляем агенту. Придуманных и «ближайших похожих»
    значений в форме не бывает.
15. **Импорт вперёд публикации.** Сломанная публикация не блокирует импорт.
16. **Лента не вытесняет ядро.** Индекс и лента — фазы 9 и 10, после закрытого
    главного цикла. Исключение: историю цен копим раньше, задним числом её
    не получить.
17. **Индекс не звонит и не создаёт объектов.** Он справочный.
18. **Три языка обязательны: грузинский, английский, русский.** Равноправны,
    все три с первого дня. Ни одной пользовательской строки в коде.
    `text-transform: uppercase` запрещён — у грузинского нет заглавных букв.

## Стиль работы, заданный владельцем

- Работать **автономно**, доводить до commit + push, не спрашивать разрешения
  на каждый шаг. Спрашивать только когда нужно продуктовое решение (что делать,
  а не как) и перед необратимыми действиями с данными.
- Общаться с владельцем **по-русски**.
- Маленькие коммиты, Conventional Commits.
- Минимальные диффы: не рефакторить то, что не входит в задачу.
- Новая зависимость — только с обоснованием.
- Отчёт в конце шага: сделано / файлы / проверки / решения / новые OPEN / риски /
  следующий шаг.

## Постоянные ограничения, заданные по ходу

- **`.claude/settings.local.json` не трогать** — файл прав, защищённая категория.
  Агент не должен сам себе расширять доступ.
- **Секреты только в `.env`**, в git не попадают никогда.
- **Neon: разрушающие операции** (удаление веток, снапшотов, `restore_snapshot`
  без `finalize: false`) — только с явного подтверждения владельца.
- Личные файлы владельца в `docs/design/` (аудио, установщики) в коммиты
  не попадают.
- **«Cleekto» в профиле сайдбара оставить как есть** — сознательное решение,
  не опечатка.
