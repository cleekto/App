# 06. Сервисы, аккаунты и доступы

## Почему здесь нет значений секретов

Ни одного ключа, пароля или строки подключения в этом файле нет — и это
осознанно, а не небрежность.

Пакет предназначен для вставки в чат с моделью. Всё, что туда попадает, уходит
на чужие серверы и остаётся в истории переписки. За перечисленными ниже
переменными стоят: доступ к боевой базе с **настоящими телефонами собственников**,
возможность выпустить любой токен сессии и возможность запускать сборщик.

Ниже — опись: **что за сервис, какой аккаунт, какая переменная, где лежит
значение**. Для приёмки проекта этого достаточно. Значения передавайте отдельно
и напрямую — и лучше не старые, а новые (см. «Перед передачей»).

## GitHub

| Что | Значение |
|---|---|
| Репозиторий | `https://github.com/cleekto/App.git` |
| Организация | `cleekto` |
| Учётная запись, с которой шли push | `shakogt-alt` |
| Ветка | `main`, единственная |

**Известная ловушка.** Организация `cleekto` и аккаунт `shakogt-alt` — разные
учётные записи. Один раз это сломало работу: push файла рабочего процесса
отклонялся с «refusing to allow an OAuth App to create or update workflow
without `workflow` scope», потому что токен выдан не тому аккаунту. Файл
`.github/workflows/collector.yml` пришлось создавать через веб-редактор GitHub.
**При передаче проверьте, у кого права на организацию.**

### Секреты GitHub Actions

| Имя | Зачем | Где задан |
|---|---|---|
| `CRON_SECRET` | Рабочий процесс `collector.yml` зовёт `/api/v1/collector/run` и подписывает вызов этим секретом | Settings → Secrets and variables → Actions |

Значение **должно совпадать** с переменной `CRON_SECRET` в Vercel, иначе
сборщик получит отказ.

### Рабочие процессы

| Файл | Когда | Что делает |
|---|---|---|
| `.github/workflows/ci.yml` | на каждый push | `typecheck`, `lint`, `test`, `build` |
| `.github/workflows/collector.yml` | по расписанию | Прогоны сборщика ленты |

Расписание сборщика (UTC; Грузия UTC+4 круглый год, перевод часов отменён):

```
45 5 * * *          → 09:45 по Тбилиси
0,15,30 6 * * *     → 10:00, 10:15, 10:30
15,30,45 11 * * *   → 15:15, 15:30, 15:45
0 12 * * *          → 16:00
```

**Почему не Vercel Cron.** Тариф Hobby даёт максимум 2 задания в сутки —
в `vercel.json` они и стоят (`30 5` и `0 11`, то есть 09:30 и 15:00).
Всё остальное внутри окон добирает GitHub Actions.

## Переменные окружения

Полный список — в `.env.example` с описанием каждой. Значения — в `.env`,
который **в git не входит никогда** (правило 8).

### Секретные — передавать отдельно, лучше новые

| Переменная | Что это | Риск при утечке |
|---|---|---|
| `DATABASE_URL` | Строка подключения **через пулер** | Полный доступ к данным агентств |
| `DIRECT_URL` | Подключение мимо пулера, нужно Prisma для миграций | То же |
| `AUTH_JWT_SECRET` | Секрет подписи access-токенов, минимум 32 байта | Выпуск любой сессии, вход под кем угодно |
| `CRON_SECRET` | Подпись вызова сборщика | Запуск сборщика извне |
| `AWS_ACCESS_KEY_ID` | Ключ Object Storage | Доступ к фотографиям и аватаркам |
| `AWS_SECRET_ACCESS_KEY` | Секрет Object Storage | То же |

### Несекретные — можно передавать как есть

| Переменная | Назначение |
|---|---|
| `AUTH_ACCESS_TTL_SECONDS` | Срок жизни access-токена |
| `AUTH_REFRESH_TTL_SECONDS` | Срок жизни refresh-токена |
| `APP_URL` | Адрес приложения |
| `DEFAULT_LOCALE` | Язык по умолчанию |
| `KLEEKTO_API_URL` | Адрес API для сборки расширения |
| `KLEEKTO_APP_URL` | Адрес приложения для расширения |
| `AWS_ENDPOINT_URL_S3` | Endpoint хранилища |
| `AWS_REGION` | Регион хранилища |
| `S3_BUCKET` | Имя бакета |

### Локальные, в `.env.example` не входят

`NEON_BRANCH`, `NEON_DATABASE_URL`, `NEON_DIRECT_URL`, `SEED_TARGET_HOST` —
вспомогательные, для переключения между ветками при разработке.

### Как получить список для Vercel

```bash
node scripts/print-vercel-env.mjs
```

## Перед передачей — что сменить

1. **`AUTH_JWT_SECRET`** — сгенерировать заново:
   ```bash
   openssl rand -base64 48
   ```
   Смена разлогинит всех. Это штатный способ аварийного отзыва доступа.
2. **`CRON_SECRET`** — сменить в двух местах согласованно: Vercel и GitHub Actions.
3. **Пароль роли PostgreSQL** — перевыпустить строку подключения в консоли Neon.
4. **Ключи Object Storage** — перевыпустить.
5. **Решить про боевую базу.** Если приёмщику она не нужна — дать только `dev`.
6. **Проверить права на организацию GitHub** и на проект Vercel.
