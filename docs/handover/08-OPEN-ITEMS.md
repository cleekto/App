# 08. Открытое, сломанное и что делать дальше

## Боевой пароль базы лежал открытым текстом в локальном файле

Найдено 2026-09-14 при сборке пакета передачи.

**Что.** Файл `docs/kleekTo-handover-2026-09-02.md` содержал полную строку
подключения с паролем роли `neondb_owner` открытым текстом.

**Куда она ведёт.** `ep-blue-sun-a5yntb5d` — **боевая ветка**
(`br-rough-waterfall-a5v5twid`), endpoint активен, последняя активность —
в день обнаружения. Доступ живой, а не от удалённой ветки.

**В репозиторий НЕ попадал.** Правило `docs/*handover*.md` в `.gitignore`
исключало этот файл с самого начала; поиск по всей истории
(`git log --all -S`) пароля не находит. Файл существовал только на машине
владельца.

**Чем это было опасно.** Тем, что пакет передачи собирается из `docs/**`
и предназначен для вставки в чат со сторонней моделью. Ещё один шаг —
и живой боевой пароль уехал бы на чужие серверы вместе с описанием проекта.
Поймано поиском по шаблонам секретов перед упаковкой.

**Что сделано.** Строка вырезана из файла, на её месте пометка. В архив
попала уже вырезанная версия; архив проверен отдельно.

**Что стоит сделать владельцу.** Перевыпустить пароль роли `neondb_owner`
в консоли Neon — как гигиену, а не как тушение пожара: пароль двенадцать дней
лежал в открытом виде на диске и мог попасть в резервную копию, синхронизацию
или другой такой же пакет. Порядок:

1. Перевыпустить пароль в консоли Neon. Прод разорвётся до шага 2 — делайте подряд.
2. Обновить `DATABASE_URL` и `DIRECT_URL` в переменных Vercel **и пересобрать**:
   Vercel запекает переменные в сборку, без Redeploy эффекта не будет.
3. Обновить локальный `.env`.

Переписывать историю git не нужно — пароля там нет.

**Почему это случилось.** Отчёт о передаче писался как рабочая заметка,
и в него вставили рабочую строку подключения. Правило 8 («секреты только
в `.env`») мысленно отнесли к коду, а не к документу. `.gitignore` спас
от публикации, но не от того, чтобы секрет пролежал на диске открытым.

## myhome.ge: форма размещения — разбор от 2026-09-09

Раньше в документации стояло «у полей нет постоянных имён, программа попадала бы
мимо». **Это было неточно.** Форма разобрана в живом браузере; вывод: заполнить
**можно**, но с оговорками.

Адрес формы: `https://statements.myhome.ge/ka/statement/create?referrer=myhome`

### Что на странице

| Показатель | Значение |
|---|---|
| Всего полей ввода | 85 |
| `input[type=text]` | 33 |
| `textarea` | 3 |
| `checkbox` | 42 (удобства) |
| `radio` | 6 (все — группа `vip-services`) |
| `input[type=file]` | 1 (фотографии) |
| **нативных `<select>`** | **0** |
| ARIA `combobox` / `listbox` | 0 |

### Чем можно зацепиться

| Якорь | Годен? |
|---|---|
| `name` | **Нет.** Только у радиогруппы `vip-services` |
| `id` | **Нет.** React `useId`: `:rl:`, `:rm:` — меняются между сборками |
| `data-testid` | **Нет.** Отсутствуют |
| Нативный `select` | **Нет.** Ни одного; выбор сделан кнопками-таблетками |
| **`label[for]` → input** | **Да.** Рабочий якорь. 36 типизированных полей имеют подпись |
| Стабильные `id` | **Два:** `total_price`, `square_price` |

### Найденные подписи (грузинский)

```
მდებარეობა (местоположение)        ქუჩა (улица)        ქუჩის ნომერი (номер дома)
მისამართი ქართულად / რუსულად / ინგლისურად (адрес на трёх языках)
საკადასტრო კოდი (кадастровый код)
სრული ფასი (полная цена → id total_price)    კვ. ფასი (цена за м² → id square_price)
ფართი (площадь)    სართული (этаж)    სართულები სულ (этажей всего)
აივნის რაოდენობა (число балконов)    ჩაწერეთ ჭერის სიმაღლე (высота потолка)
```

### Три ловушки

1. **Одинаковые подписи.** `ფართი` («площадь») встречается **семь раз** —
   общая площадь, балкон, кухня и прочие неразличимы по подписи. Понадобится
   привязка к разделу или к порядку внутри секции.
2. **Непереведённые машинные ключи.** Пять подписей сейчас выглядят как
   `mainInformationSection:latitude`, `contactInformationSection:street-number`.
   Это течёт из-за отсутствующего перевода. **Не опираться на них** — станут
   грузинским текстом, как только myhome допереведёт.
3. **Ленивый монтаж.** Состав полей меняется по мере прокрутки разделов — та же
   ловушка, что мастер ss.ge. Механизм ожидания (`hasFields` + `MutationObserver`)
   уже написан и применим здесь.

### Что реально автозаполняемо

Цена, цена за м², площадь, этаж, этажей всего, балконы, кадастровый код, адрес
на трёх языках, описание — **порядка 10–12 полей**, то есть основная масса
ручного набора.

Выбор типа, сделки, статуса, города, района — кнопки-таблетки; по аналогии
с ss.ge их честнее пометить `manual_only`, чем кликать наугад.

## Рекомендуемый порядок работ для того, кто примет проект

1. **Прочитать `01-PRODUCT.md` и `05-DELTA.md`.** Без них правила выглядят

   ошибки вместо «Application error»; не плодить черновики публикаций.
3. **Довести помощника ss.ge до конца мастера** — дозаполнять поля по мере
   прохождения шагов. Наблюдатель уже стоит; решить, как не заводить лишние
   публикации на каждый шаг.

5. **Ранжирование по выгодности** — то, ради чего лента задумана.
6. **Договориться с TNET об API myhome** — снимет костыль «Собрать с myhome.ge».

## Правила проверки, выведенные из ошибок этого проекта

Они дорого дались, их стоит сохранить:

- **Тесты не доказывают, что код вызывается.** Заполнение формы было написано,
  покрыто 33 тестами и не вызывалось из `content.ts` четыре дня. Проверяйте
  на живом сайте и на собранном расширении.
- **Проверяйте вывод замера, а не только его наличие.** Дважды вывод делался
  по неполному обходу данных и оказывался ложным.
- **Пустой `catch` съедает отказы.** Схема приёма отвергала каждую пачку
  от myhome несколько дней, и узнать об этом было неоткуда.
- **`NULL NOT IN (…)` в SQL — не истина.** Один такой фильтр скрыл всю ленту
  на проде, а в dev не проявлялся, потому что там не было данных для срабатывания.
- **Встроенная панель предпросмотра врёт про этот проект.** Streaming-страницы
  в ней зависают на скелетоне, а событие `close` у `<dialog>` не приходит вовсе.
  Дважды из-за этого едва не были заведены несуществующие дефекты. Сверяйтесь
  с исходником и с настоящим Chrome.
