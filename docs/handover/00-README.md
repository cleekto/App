# Передача проекта kleekTo — оглавление пакета

Пакет собран 2026-09-14 для передачи проекта другой модели (ChatGPT) или
другому разработчику. Он самодостаточен: чтобы понять проект, ничего, кроме
этих файлов и репозитория, читать не нужно.

## Порядок чтения

1. `01-PRODUCT.md` — без понимания рабочего цикла агента остальное бессмысленно.
2. `05-DELTA.md` — там объяснено, почему код местами не совпадает с исходной
   спецификацией. Без этого файла приёмщик решит, что видит ошибки.
3. `03-ARCHITECTURE.md` — как устроено.
4. `08-OPEN-ITEMS.md` — что не доделано и что сломано.

Остальное — по потребности.

## Чего в пакете НЕТ и почему

**Значений секретов.** Ни ключей, ни паролей, ни строк подключения. Причина
прямая: эти файлы предназначены для вставки в чат с моделью, а всё вставленное
оседает в истории переписки на чужих серверах. В `06-ACCOUNTS.md` перечислено,
какой сервис, какой аккаунт, какая переменная и где лежит её значение — этого
достаточно, чтобы принять проект. Сами значения передавайте отдельно и напрямую.

**Фикстур.** `docs/fixtures/**` не входит в git и в пакет: там сохранённые
страницы ss.ge и myhome.ge с настоящими телефонами и именами собственников,
а в одной — JWT с почтой владельца. Это чужие персональные данные. Тесты,
которые их читают, помечены `skipIf` и на чужой машине просто пропускаются.

**`node_modules` и сборок.** Восстанавливаются командой `pnpm install`.

## Что стоит сделать перед передачей

1. **Смените секреты.** `AUTH_JWT_SECRET`, `CRON_SECRET`, пароль роли
   PostgreSQL, ключи Object Storage. Смена `AUTH_JWT_SECRET` разлогинит всех —
   это штатный способ отзыва доступа.
2. **Решите, даёте ли доступ к боевой базе.** Там настоящие телефоны
   собственников. Для приёмки достаточно dev-ветки Neon с сид-данными.
3. **Проверьте, кто владелец репозитория и проекта Vercel.** Сейчас
   `github.com/cleekto/App`, аккаунт GitHub `shakogt-alt` и организация
   `cleekto` — исторически это разные учётные записи, и один раз это уже
   ломало push (см. `06-ACCOUNTS.md`).

## Как объяснить приёмщику правила игры

Проект написан по жёсткому своду правил. Они не стилистические — каждое
закрывает конкретный способ испортить данные или нарваться на блокировку
площадкой. Полный список в `01-PRODUCT.md`, но три самых важных:

- **Объект появляется только по «Согласен»** — ни лента, ни фоновый сбор
  объектов не создают;
- **телефон раскрывает человек** — расширение никогда не имитирует нажатие
  «показать номер»;
- **публикует человек** — расширение заполняет форму площадки, но никогда
  не нажимает «Опубликовать».

Модель, которая этого не знает, «починит» их как баги в первый же день.
