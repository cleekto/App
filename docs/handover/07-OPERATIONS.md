# 07. Эксплуатация: запуск, сборка, развёртывание

## Команды

```bash
pnpm dev                # веб-приложение, http://localhost:3000
pnpm typecheck
pnpm lint               # eslint + проверка форматирования
pnpm format             # применить форматирование
pnpm test               # 625 тестов, база не нужна
pnpm test:integration   # нужна живая база
pnpm build
```

```bash
pnpm db:up              # PostgreSQL в Docker
pnpm db:down
pnpm db:generate        # клиент Prisma
pnpm db:migrate         # применить миграции
pnpm db:seed            # тестовые данные: 2 компании — для проверки изоляции
pnpm db:studio
```

### Почему всё через pnpm, а не напрямую

Команды идут через `scripts/with-env.mjs` — он подаёт единый корневой `.env`
инструментам, которые ищут его в разных местах. Поэтому `next` и `prisma`
запускаются через `pnpm`, а не напрямую.

## Сборка расширения

```bash
pnpm --filter @kleekto/extension build
```

Результат — `apps/extension/dist/`. Установка:

1. `chrome://extensions`
2. Developer mode → включить
3. **Load unpacked** → указать `apps/extension/dist`

**Адрес сервера запекается в бандл** из `KLEEKTO_API_URL` на момент сборки.
Пересобрали под другой адрес — переустановите у всех агентов.

**После каждой пересборки** нажмите ↻ на карточке расширения, иначе Chrome
продолжит выполнять старый код. Это уже приводило к ложному выводу
«правка не помогла».

Подробнее — `docs/extension-install.md`.

## Развёртывание

Vercel собирает из `main` автоматически. Команда сборки:

```
pnpm --filter @kleekto/db exec prisma generate
  && node ../../scripts/deploy-migrate.mjs
  && next build
```

Миграции применяются на боевой сборке автоматически.

**Переменные запекаются в сборку.** Vercel не применяет их к уже собранному
деплою — после смены переменной нужна пересборка.

Подробности, включая резервные копии и восстановление, — `docs/DEPLOYMENT.md`.

## Диагностика

### Каждая страница отвечает 500

Смотреть **Runtime Logs** в Vercel, не Build Logs. Частые причины перечислены
в `docs/DEPLOYMENT.md` §8а. Самая частая — незаданная или устаревшая переменная.

Эндпоинт `/api/v1/health` называет причину: незаданные переменные хранилища,
недоступность базы, `auth_failed` (перевыпустить строку подключения в Neon).

### Лента пуста

Порядок проверки:

1. Есть ли записи: `select count(*) from listing_observations`
2. Не отфильтровано ли всё: у ленты есть фильтр по телефонам компании,
   и он уже один раз скрывал весь индекс (`NULL NOT IN (…)` в SQL — не истина).
3. Дошли ли пачки от расширения: окошко расширения показывает след последнего
   сбора («Собрано N минуту назад» либо отказ).
4. Логи сборщика: GitHub Actions → `collector.yml` → последний прогон.

### Расширение ничего не делает на странице площадки

Быстрая проверка в консоли на странице ss.ge или myhome:

```js
/\[native code\]/.test(window.fetch.toString())
```

`true` — `listen.js` **не отработал**: расширение не загружено, отключено
или стоит в другом профиле Chrome.
`false` — отработал, ищите причину дальше.

Есть ли интерфейс:

```js
!!document.getElementById('kleekto-root')
```

### Windows: `prisma generate` падает при сборке

Запущенный `pnpm dev` держит бинарник движка запросов. Остановите dev-сервер
и повторите сборку. Это не дефект кода.

## Прод: как проверить, что деплой дошёл

Статус деплоя по коммиту:

```bash
gh api repos/cleekto/App/commits/<sha>/status \
  --jq '{state:.state, statuses:[.statuses[]|{context,state}]}'
```

Поведенческая проверка надёжнее: запросить изменившийся endpoint и посмотреть
код ответа. Например, после переноса фотографий с архива на файлы старый
маршрут стал отдавать 404, а новый — 401 для неавторизованного.
