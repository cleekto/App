# Контракты API

**Дата:** 2026-08-31. **Фаза:** 1. **Машиночитаемая версия:** `openapi.yaml` в этом же каталоге.
**Основание:** инвариант 8 (версионирование), правило 5 (`companyId` из контекста), промпт §5.3, §6.4, §6А.4.

---

## 1. Общие правила

**Базовый путь:** `/api/v1`. Версия в пути — инвариант 8. Ломающее изменение контракта означает `/api/v2`, а не «дополнительное поле, которое старый клиент проигнорирует»: расширение обновляется у агентов не мгновенно, и сервер обязан какое-то время обслуживать обе версии.

**Формат:** JSON, UTF-8. Даты — ISO 8601 с зоной. Деньги — `{ "amount": number, "currency": "USD" }`, без конвертации (Q13).

**Аутентификация:** `Authorization: Bearer <access>` для расширения; httpOnly cookie для веба. Один и тот же сценарий, разный транспорт — подробности в `ADR-0003-auth.md`.

### `companyId` в запросе не принимается никогда

Правило 5, и это касается контракта буквально: **ни один endpoint не имеет параметра `companyId`, `teamId` или `userId` владельца данных**. Они берутся из сессии. Если такой параметр появится в схеме — это дефект, а не удобство.

Поля `companyId`, пришедшие в теле запроса, **молча игнорируются**, а не вызывают ошибку. Ошибка подсказала бы атакующему, что параметр вообще существует.

### Модель ошибок

```jsonc
{
  "error": {
    "code": "FORBIDDEN",
    "message": "Недостаточно прав для изменения объекта",
    "details": { }
  }
}
```

| Код | HTTP | Когда |
|---|---|---|
| `VALIDATION_ERROR` | 400 | Тело не прошло схему. `details.fields[]` перечисляет поля |
| `UNAUTHENTICATED` | 401 | Токена нет, истёк или отозван |
| `FORBIDDEN` | 403 | Ресурс **своей компании**, но роль не позволяет |
| `NOT_FOUND` | 404 | Ресурса нет **либо он принадлежит другой компании** |
| `CONFLICT` | 409 | Нарушение уникальности, повторное подтверждение публикации |
| `DUPLICATE_BLOCKED` | 409 | `EXACT` при импорте, второй копии не будет |
| `PHONE_NOT_REVEALED` | 422 | Технический резерв, см. ниже |
| `RATE_LIMITED` | 429 | Ограничение частоты |
| `INTERNAL` | 500 | Всё остальное. Наружу не уходит ничего, кроме кода и идентификатора запроса |

**Чужая компания даёт 404, а не 403.** Разница существенна: 403 подтверждает, что объект существует, и это уже утечка — по перебору идентификаторов можно оценить размер базы конкурента. Отсутствие и запрет снаружи неразличимы (R-04). Внутри компании, где факт существования объекта не секрет, возвращается честный 403.

**`PHONE_NOT_REVEALED` существует, но в норме не используется.** Правило 11 требует, чтобы при нераскрытом телефоне запрос к API **вообще не уходил** — блокирует расширение, на клиенте. Серверная проверка стоит второй линией: если запрос без телефона всё-таки пришёл, значит адаптер сломан или кто-то обращается к API напрямую. Оба случая — повод отказать и записать событие.

### Ограничение частоты

| Группа | Лимит |
|---|---|
| `POST /auth/login` | 10 попыток / 15 мин на IP и на email |
| `POST /import/listing` | 60 / мин на пользователя |
| `POST /observations/*` | 300 / мин на пользователя |
| `POST /telemetry/*` | 120 / мин на пользователя |
| Остальное | 600 / мин на пользователя |

Лимит на импорт намеренно щедрый: агент в хороший день импортирует десятки объектов, и упереться в лимит на нормальной работе он не должен.

## 3. Импорт — главный endpoint продукта

### `POST /import/listing`

Вызывается при действии **«Согласен»** и только после разговора с собственником (R14, J1).

**Запрос:**

```jsonc
{
  "source": "SS_GE",
  "sourceUrl": "https://ss.ge/...",
  "externalId": "12345678",

  "title": "3-комнатная в Сабуртало",
  "propertyType": "APARTMENT",
  "transactionType": "SALE",

  "price": 145000,
  "currency": "USD",

  "area": 78,
  "rooms": 3,
  "bedrooms": 2,
  "floor": 5,
  "totalFloors": 12,

  "address": "Сабуртало, ул. Вашлованская 12",
  "description": "...",
  "photos": ["https://..."],

  "owner": { "name": "Гиорги", "phone": "+995 555 12 34 56" },

  "attributes": { },

  "parserVersion": "ss.ge@1.0.0",
  "missingFields": ["floor"],

  "acknowledgedDuplicateOf": []
}
```

**Ответ** — по контракту `duplicate-detection.md` §4: `result`, `verdict`, `property`, `matches[]`, `actions[]`.

**`acknowledgedDuplicateOf` — механизм «Добавить всё равно».** Агент получает предупреждение со списком совпадений и повторяет тот же запрос, перечислив идентификаторы, которые он сознательно признал не-дублями. Сервер создаёт объект и пишет в `ActivityLog`, какие именно совпадения были проигнорированы и кем.

Выбран этот способ, а не токен решения: он не требует состояния на сервере между двумя запросами (MV3 усыпляет service worker, R-09) и не ломается при повторе. При `EXACT` подтверждение не действует — второй копии не будет никогда.

**Идемпотентность:** ключ `(teamId, source, externalId)`, при отсутствии `externalId` — `(teamId, canonicalUrl)` (Q43). Повтор не создаёт объект: обновляются цена, `lastSeenAt` и `lifecycle` у `SourceListing`, пишется `ActivityLog`, возвращается `EXACT` (Q21).

**Обязательное:** телефон. Его отсутствие — блокировка на клиенте (правило 11), `PHONE_NOT_REVEALED` на сервере.

### `POST /observations/state` — три остальных исхода

«Отказ / не звонить», «Недозвон», «Перезвонить через N дней». **Объекта не создают** (J4).

```jsonc
{
  "source": "SS_GE",
  "externalId": "12345678",
  "canonicalUrl": "https://ss.ge/...",
  "state": "refused" | "no_answer" | "callback" | "skipped",
  "callbackAt": "2026-09-05T10:00:00+04:00",
  "doNotCallCompanyWide": false,
  "note": "перезвонить после отпуска",
  "observation": { }
}
```

**`doNotCallCompanyWide` — отдельный флаг, а не отдельное состояние** (Q40а, §5Б.3). Обычный отказ действует на команду: другая команда может попробовать, конкуренция разрешена. «Просил не звонить» действует на всю компанию и никогда не сбрасывается изменением цены.

Блок `observation` несёт данные объявления для индекса. **Телефон в нём сохраняется всегда** (J6): иначе то же объявление всплывёт в ленте завтра, и второй агент команды позвонит тому же собственнику.

## 4. Объекты

| Метод | Путь | Права |
|---|---|---|
| `GET` | `/properties` | Область по роли: `ADMIN`/`MANAGER` — компания, `AGENT` — команда (Q5) |
| `POST` | `/properties` | Ручное создание, `origin = manual` (Q29) |
| `GET` | `/properties/{id}` | |
| `PATCH` | `/properties/{id}` | `AGENT` — только свои (Q1) |
| `DELETE` | `/properties/{id}` | `MANAGER` в команде, `ADMIN` в компании |
| `POST` | `/properties/{id}/assign` | `MANAGER`, `ADMIN` (Q3) |
| `PATCH` | `/properties/{id}/status` | Смена статуса воронки |

**`GET /properties` возвращает объекты своей команды полностью, чужих команд — урезанно.** Урезанный вид не содержит телефона собственника и описания (Q40, J23). Это одно поле в ответе — `visibility: "full" | "limited"`, — и клиент обязан его учитывать. Полагаться на то, что клиент «просто не покажет», нельзя: правило 6 запрещает.

**`origin` возвращается всегда** и не редактируется через API. Поставить объекту `origin = consent` задним числом нельзя ни одним запросом — иначе правило R14 обходится за один PATCH.

## 5. Публикация

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/properties/{id}/publish-check?source=` | Предупреждение «уже размещён» **до** заполнения (I22, P9) |
| `POST` | `/publications/draft` | Черновик по белому списку + `publisher` |
| `POST` | `/publications/{id}/filled` | Отчёт `FillResult` от расширения |
| `POST` | `/publications/{id}/confirm` | Подтверждение факта публикации |
| `GET` | `/publications?propertyId=` | Список публикаций объекта |
| `GET POST PATCH DELETE` | `/publish-profiles` | Профили: ведут `ADMIN` и `MANAGER` (I15) |

### `POST /publications/draft` — где обеспечено правило 13

**Черновик собирается на сервере**, а не расширением. Это принципиально: правило R12 запрещает контактам собственника попадать на площадку, и единственный способ гарантировать это — не давать расширению данных, которые оно могло бы туда вписать.

Ответ содержит ровно белый список полей из §6А.4 и блок `publisher` из профиля публикации. **Блока `owner` в схеме ответа не существует.** Не «пустой», не «опциональный» — его нет в типе, и тест проверяет, что он не появился.

Дополнительно: `publicDescription` очищается от телефонов **во всех нормализациях** и от имени собственника (I7a). Тест на это обязателен (I7b) — это единственный риск в проекте, где одна ошибка бьёт по третьему лицу, а не по нам (R-25).

Профиль применяется **по умолчанию, без диалога** — требование «одним кликом» не допускает выбора (P4). Какой профиль применён, видно в ответе и в отчёте о заполнении.

### `POST /publications/{id}/confirm`

Единственный способ перевести публикацию в `published` (инвариант 13, I17). Без него статус остаётся `filled`.

Повторное подтверждение той же публикации — `CONFLICT`, а не молчаливое обновление: два разных `externalId` у одной записи означают, что что-то пошло не так, и это должно быть видно.

**Смена статуса воронки происходит не здесь, а на `/filled`** (J13). Расширение не знает, нажал ли агент «Опубликовать».

## 6. Лента и индекс (фазы 9–10)

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/feed` | Лента «Выгодные объявления» |
| `POST` | `/feed/{observationId}/open` | Мягкая блокировка: «в работе у Нино» (K29) |
| `POST` | `/observations` | Пассивный сбор из расширения |

**`GET /feed` возвращает область компании, а не агента** (K25). Фильтры — параметры запроса и влияют только на выдачу, не на права (K28).

Каждая позиция ленты **обязана нести причину** (K19):

```jsonc
{
  "observationId": "...",
  "deviation": -0.12,
  "sampleSize": 34,
  "reasonHuman": "На 12% ниже похожих в Сабуртало",
  "isSuspicious": false,
  "workingNow": { "userName": "Нино", "sinceMinutes": 3 }
}
```

**`sampleSize` возвращается всегда.** Если он ниже порога достаточности (дефолт 20), `deviation` равен `null`, а `reasonHuman` говорит «мало данных по этому району» (K16). Показать отклонение без размера выборки — прямой путь к тому, что агент дважды проверит цифру, увидит ерунду и перестанет доверять ленте (R-33).

| Метод | Путь |

Предпросмотр показывает дубли **внутри самого файла** до записи (L7, L8). Все созданные объекты получают `origin = legacy_import` и `migrationBatchId` — без обратной ссылки откат превращается в угадывание по дате.

## 8. Телеметрия и аналитика

| Метод | Путь | Ограничение |
|---|---|---|
| `POST` | `/telemetry/parse-failure` | **Без персональных данных** (D14) |
| `POST` | `/telemetry/fill-failure` | То же |
| `GET` | `/analytics/dashboard` | Область по роли (F2) |

Схема события об ошибке парсинга содержит `source`, `parserVersion`, `url`, `selectorKey`, `errorCode` — и больше ничего. Имени, телефона и содержимого страницы в ней нет: тип запрещает их передать.

Событие уходит обычным POST и пишется синхронно. Очереди нет — инвариант 10, зафиксировано в C-13.

## 9. Что решено в этом документе и требует внимания

| Решение | Уровень |
|---|---|
| Чужая компания → 404, своя без прав → 403 | `RECOMMENDED`. Безопаснее, но усложняет отладку: разработчик увидит 404 там, где ожидал 403 |
| «Добавить всё равно» через `acknowledgedDuplicateOf` вместо токена решения | `RECOMMENDED`. Не требует состояния между запросами, устойчиво к засыпанию service worker |
| `visibility: full \| limited` в списке объектов | `DERIVED` из Q40 |
| `sampleSize` в каждой позиции ленты | `DERIVED` из K16 |
| `PHONE_NOT_REVEALED` как вторая линия | `DERIVED` из правила 11 |
| Лимиты частоты | `RECOMMENDED`. Числа взяты с запасом, уточняются на пилоте |
