## Легенда уровней

| Уровень | Значение |
|---|---|
| `CONFIRMED` | Владелец сказал прямо (S§4, S§14, или помечено как подтверждённое в P) |
| `DERIVED` | Логически следует из подтверждённого |
| `RECOMMENDED` | Инженерное предложение, требованием не является |
| `OPEN` | Требует решения владельца — см. `open-questions.md` |

Колонка **MVP**: `Да` — входит в Definition of Done (S§48, P§10); `Нет` — явно отложено (S§34, P§9); `Каркас` — кода нет, но архитектура обязана это принять без переписывания.

## Что промпт поднял в уровне по сравнению со спецификацией

Спецификация помечает эти решения как инженерные рекомендации (S§7, S§11, S§18, S§31, S§36). Промпт владельца превратил их в **обязательные инварианты** (P§4). Разница важна: это уже не мои предложения, отказаться от них нельзя без явного решения владельца.

| Решение | В спецификации | В промпте |
|---|---|---|
| `Property` отделён от `SourceListing` | RECOMMENDED (S§7, S§31) | Инвариант P§4.5 |
| `PipelineStatus` вместо захардкоженных статусов | RECOMMENDED (S§11) | Инвариант P§4.4 |
| `ActivityLog` с первого дня | RECOMMENDED (S§18) | Инвариант P§4.7 |
| Архитектура адаптеров источников | RECOMMENDED (S§26) | Инвариант P§4.6 |
| Версионирование API | DERIVED (S§36) | Инвариант P§4.8 |
| Дедупликация только внутри компании | не сформулировано | Инвариант P§4.9; в v2.2 переписан в таблицу пяти проверок с явно заданными областями |
| Правило раскрытого телефона | отсутствует | CONFIRMED P§6.1–6.2 |

Обратное движение тоже есть: спецификация допускает «Next.js API **или** отдельный TypeScript backend» (S§38) — эта развилка так и осталась открытой (Q19).

## Критический путь MVP

```
A1..A13 (арендаторы, роли, изоляция)  +  I13 (профили публикации)
        ↓
B3..B17 (импорт)  →  C1..C20 (дедупликация)      ← ядро продукта, делается без Chrome
        ↓
J1..J24 (согласие, воронка, origin, командная область)  ← вход объекта в базу
        ↓
I7, I16, I19..I21, I23 (ядро публикации, Фаза 4Б) ← тоже без Chrome
        ↓
L1..L15 (миграция базы агентства, Фаза 4В)        ← без неё не будет пилота
        ↓
[ фикстуры от владельца: страницы объявлений + формы размещения + страницы результатов поиска ]
        ↓                                           ← ЕДИНСТВЕННЫЙ ВНЕШНИЙ БЛОКЕР
D1..D21 (расширение, импорт)  +  J2..J9 (четыре пункта меню)
        ↓
D22..D26 + I2..I12 (расширение, заполнение формы, Фаза 6Б)
        ↓
E1..E17 (веб CRM) + I28  →  F1..F8 + I29 + J24 (аналитика, AUDIT)
        ↓
        ══ ГЕЙТ ФАЗЫ 8: главный цикл закрыт ══     ← правило R15
        ↓
K2..K9 (индекс и пассивный сбор, Фаза 9)  →  K12..K32 (лента, Фаза 10)
```

Порядок из промпта (ядро импорта раньше расширения) совпадает с рекомендованным порядком спецификации (S§43, S§46). Публикация везде идёт следом за импортом — правило R13 и требование I30. Лента и индекс стоят **за гейтом фазы 8** — правило R15 и требование K32. До получения фикстур не пишется ни один селектор, ни одно значение словаря соответствий и ни строки сборщика индекса — S§44, P R2, K7.

**Одно исключение из порядка, и оно обязательное.** Накопление истории цен (K8) включается сразу, как только фаза 5 покажет, что отдают страницы результатов, — без ленты, без ранжирования, без интерфейса. У истории есть дата начала, и задним числом её не получить. Это единственное место, где нарушение порядка фаз не только допустимо, но и требуется.

**Раздел J роста не дал, он дал смещение.** Двадцать пять его требований почти не добавляют кода — они меняют смысл уже описанного. Кнопка импорта перестала создавать объект; между извлечением данных и записью в базу встал телефонный разговор. Разделы B, C, D переписывать не нужно, но читать их теперь следует через J1: извлечение данных и создание объекта — разные события, разделённые звонком.
