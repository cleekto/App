# Аудит 6 сентября 2026: бизнес-логика и интерфейс

Проверка того, что построено 5–6 сентября: правка объектов, области видимости,
чат с вложениями, фильтры доски, значки непрочитанного. Всё проверено на
запущенном приложении и живой базе. Там, где вывод сделан только чтением кода,
это сказано отдельно.

Разбор движения — по методу Эмиля Ковальского (скиллы `emil-design-eng`
и `review-animations`, прочитаны с диска: установщик кладёт их
в `~/.agents/skills/`, и Claude Code в его списке целевых агентов нет).

## 1. Что нашлось в бизнес-логике

### B1. Область агента обходилась через публикации — критично, исправлено

Правило «агент видит только свои объекты» закрывало две двери из шести.
Карточка чужого объекта отдавала `403`, а те же данные свободно выдавал
черновик публикации: право там осталось командным и проверялось по `teamId`,
а не по владельцу.

Найти чужой объект тоже ничего не стоило: `GET /api/v1/tasks` отдавал задачи
всей команды вместе с `propertyId`.

Цепочка, снятая с живой системы **до** исправления:

```
GET  /api/v1/tasks                         → 200   propertyId: 3d86f67d…
GET  /api/v1/properties/3d86f67d…          → 403   закрыто
POST /api/v1/properties/3d86f67d…/publications
                                           → 200   address: «Чавчавадзе 37»
                                                   district: «Ваке», price: 310000
                                                   area: 92, rooms: 4
```

Та же цепочка **после**:

```
GET  /api/v1/tasks                         → 0 задач по чужому объекту
GET  /api/v1/properties/3d86f67d…          → 403
GET  /api/v1/properties/3d86f67d…/publications  → 403
POST /api/v1/properties/3d86f67d…/publications  → 403
GET  /api/v1/properties/3d86f67d…/comments      → 200, пустой список
```

Комментарии отвечают `200` с пустым списком, а не отказом. Так оставлено
намеренно: пустой ответ раскрывает меньше, чем отказ, — он не подтверждает,
что объект существует.

**Что изменено.** Области `publication.create`, `publication.read`,
`task.*` и `comment.*` у агента сужены с команды до «своего». Везде, где
проверка области шла по объекту, добавлен владелец: без него `undefined`
не равен никому, и агент получал бы отказ даже на собственной карточке.

### B2. Задача вела в тупик — исправлено следствием B1

Задачи были видны по команде, объекты — только свои. Руководитель ставил
задачу «позвонить по объекту», агент видел её в списке, нажимал — и получал
отказ. Тот же тупик был у комментариев.

### B3. Решения владельца, принятые 6 сентября

| Вопрос | Решение |
|---|---|
| Чем должно быть правило «агент видит только свои» | Границей доступа. Публикации сужены |
| Задачи | Личные у агента. Командную ставит только руководитель (`assign`) |
| Связь с собственником | Личная |
| Название «перезвоны» | Заменено на «связаться» |

### B4. Что проверено и оказалось целым

| Инвариант | Чем подтверждён |
|---|---|
| Дедупликация в области **команды** при «Согласен» | `dedup/engine.ts` берёт `ctx.teamId` напрямую, а не область чтения. Именно это оправдывает сужение показа: от повторного звонка защищает проверка, а не видимость |
| Правило 13 — контакты собственника не уходят на площадку | Черновик публикации вернул адрес и цену и ни имени, ни телефона. 22 теста очистки |
| Правило 0 — объект вне «Согласен» помечается | Ручное заведение проставляет `origin: manual` явно |
| Состояние обзвона привязано к команде | `@@unique([observationId, teamId])`; колонки «чьё» нет — отсюда и трактовка «моё = я последним отметил» |
| Правило 11 — телефон раскрывает человек | 61 тест расширения, включая блокировку всех четырёх исходов |

### B5. Остаётся открытым

- **Что значит «своё» у объявления и публикации.** В аналитике принято:
  у объявления — «мною импортированное», у публикации — «мною созданная».
  Это трактовка, а не решение владельца.
- **Связь остаётся одна на команду.** Если по объявлению отметится второй
  агент, напоминание перейдёт к нему. Разделить связи между двумя агентами
  одной команды нельзя без нового поля и миграции.

## 2. Интерфейс: движение

Формат обязан быть таблицей «до → после» — этого требует сам скилл.

| Было | Стало | Почему |
|---|---|---|
| `group-hover:scale-[1.04]` без медиазапроса (3 места) | `@media (hover:hover) and (pointer:fine)` вокруг | На касании hover срабатывает по тапу: фотография дёргалась при каждом нажатии на строку. В 19 других местах гейт стоял, эти три были забыты |
| `transition-duration: 0.01ms !important` на всё при reduced-motion | Только укорачивание времени плюс `transform: none` на наведении и нажатии | «Меньше движения» ≠ «ноль анимаций». Гасла и плавность цвета, по которой видно, что состояние сменилось |
| Окно правки появлялось мгновенно | `opacity 0→1` + `scale(.96)→1`, 180 мс, `--ease-out`, origin центральный | Элемент, возникающий без перехода, читается как сбой. Модалка — исключение из правила «расти от кнопки»: она не привязана к триггеру |
| `skeleton-sheen 1.5s var(--ease-in-out) infinite` | `1.5s linear infinite` | Постоянное движение должно быть равномерным. С плавной кривой блик замирал на краях — получался пульс, а не перелив |
| `active:scale-[0.97]` только у `Button` и карточки доски | То же у правки, вложения, удаления фото, тем | Половина кнопок отвечала на нажатие, половина молчала |

### Две ошибки, пойманные только живой проверкой

Обе — в моей же правке модального окна, и обе невидимы там, где «меньше
движения» выключено.

1. **Открытое окно оставалось прозрачным.** Конечное состояние нигде не было
   задано явно: `@starting-style` давал стартовое значение, а возвращаться
   было некуда — у `dialog` нет своего `opacity`.
2. **Закрытое окно оставалось с `display: block`** — пустой блок, перехватывающий
   нажатия. Дискретный переход `display`/`overlay` не доигрывал, потому что
   мой же глобальный список свойств вырезал его из перехода.

Итог: под «меньше движения» у окна нет перехода вовсе. Без перехода
`@starting-style` не применяется, и окно просто появляется и просто исчезает —
ровно то, о чём человек и просил.

**Анимированный путь проверить не удалось**: в браузере проверки
`prefers-reduced-motion` включён системно. Это стоит посмотреть глазами
на машине без этой настройки.

### Что в движении было сделано верно и осталось

- Кривые заданы своими и совпадают с рекомендованными источником:
  `cubic-bezier(0.23, 1, 0.32, 1)` и `cubic-bezier(0.77, 0, 0.175, 1)`.
- Длительности 120 / 180 / 240 мс — все под порогом 300.
- Ни одного `transition: all`, ни одного `scale(0)`, ни одного `ease-in`
  (последний запрещён отдельным комментарием в коде).
- `@starting-style` вместо ключевых кадров: переход прерывается и разворачивается.
- Двигаются только `transform`, `opacity` и `background-position`.
- Кольцо фокуса одно на весь продукт: `:focus-visible`, обводка 2px со смещением.

**Решение по разделу: принять.** Ни одного блокирующего признака по списку
источника.

## 3. Интерфейс: цвет, читаемость, удобство

Контраст считался по формуле относительной яркости WCAG 2.1, размеры снимались
через `getBoundingClientRect` с живой страницы.

| Что | Было | Стало | Норма |
|---|---|---|---|
| Третичный текст на белом | `#8991a4` — 3.16 | `#676e80` — 5.10 | 4.5 |
| Он же на приглушённом фоне | 2.85 | 4.60 | 4.5 |
| Граница поля ввода | `#ccd2e2` — 1.51 | `#828a9f` — 3.45 | 3.0 |
| Высота кнопки правки | 21 px | 24 px | 24 |

Третичный текст стоял в 39 местах: даты, имена ответственных, вторые строки,
подсказки в полях — ровно там, где читают мелкое и быстро. Рядом с токеном
лежал комментарий «4.56 на приглушённом фоне»: цифра была не измерена,
а придумана.

Для очертаний управляющих элементов заведён отдельный токен
`--color-border-field`: у них своя норма контраста, и декоративная линия
её не берёт.

### Прочее

- **Список комнат в чате** был без предела высоты: на узком экране, где две
  колонки схлопываются в одну, переписка уезжала за пределы экрана.
  Стало 22rem со своей прокруткой — проверено на 22 комнатах.
- **Заливка на плитках аналитики** переехала с «новых сегодня» на «объектов
  в базе»: дневной счётчик к обеду ещё ноль и в понедельник ничего не говорит.
- **Цвет комнаты** теперь раздаётся по кругу при создании. Замысел «нужную
  комнату находят по цвету» не работал: цвет никто не выбирал, и список был
  одинаково фиолетовым.
