# CLAUDE.md — Cleekto

Файл читается в начале каждой сессии. Держи его коротким и актуальным.

## Что это за проект

**Cleekto** — SaaS CRM для агентств недвижимости (рынок — Грузия).

Рабочий цикл агента:

```
лента рекомендаций → открыл объявление → раскрыл телефон → позвонил
   → «Согласен» → объект в базе, статус «В базе»
   → «Заполнить» на форме площадки → разместил сам → «Принято в работу»
```

Кроме «Согласен» в меню ещё три исхода разговора: «Отказ / не звонить», «Недозвон / перезвонить», «Перезвонить через N дней». **Они объект не создают** — помечают объявление в ленте.

**Приоритет №1 всегда:** скорость и надёжность главного цикла — от объявления до объекта и обратно до размещённого объявления. Лента, индекс и аналитика уступают ему всегда.

## Правила, которые нельзя нарушать

0. **Объект появляется только по «Согласен».** Ни лента, ни индекс, ни фоновый процесс `Property` не создают. Исключения — ручное создание и миграция, оба помечаются полем `origin`.

1. **Маркируй уровни:** `[CONFIRMED]` / `[DERIVED]` / `[RECOMMENDED]` / `[OPEN]`. Рекомендация — не требование.
2. **Не выдумывай** DOM ss.ge/myhome.ge, состав форм размещения, external ID, доступность телефонов, ToS, внешние API. Нет проверенных данных → запроси фикстуры и остановись.
3. **Гейты:** фаза заканчивается отчётом и стопом. Следующая фаза — только по команде `GO PHASE N`.
4. **«Готово» = запущены** `typecheck`, `lint`, `test`, `build`, вывод в отчёте.
5. **`companyId` — только из authenticated context.** Никогда из тела запроса. У каждого endpoint есть негативный тест на чужую компанию.
6. **Права — на сервере.** Фронтенд только прячет кнопки.
7. **Никаких заглушек**, mock-данных в production-путях, `any`, пустых `catch`.
8. **Секреты — только в `.env`**, `.env.example` держи актуальным.
9. **Применённые миграции не редактируются.**
10. **PII (телефоны, имена, фото собственников)** не логируются и не попадают в фикстуры в исходном виде.
11. **Правило раскрытого телефона.** Агент сам нажимает «показать телефон» на сайте — расширение читает уже раскрытый DOM. Оно **никогда** не имитирует этот клик, не дёргает внутренние endpoint'ы сайта и **никогда не импортирует объект без телефона молча**: нет номера → блокирующее сообщение «Сначала откройте номер телефона», запрос к API не уходит. Метод `isPhoneRevealed()` обязателен в интерфейсе каждого адаптера чтения.
12. **Правило «публикует человек».** Расширение заполняет форму размещения, но никогда не отправляет её, не ставит галочку согласия, не решает капчу, не работает в фоне и не поднимает объявления. Кнопку «Опубликовать» нажимает агент.
13. **Контакты собственника не уходят на площадку.** Черновик публикации собирается на сервере по белому списку полей и не содержит `OwnerContact`; описание очищается от телефонов. Проверяется тестом.
14. **Частичное заполнение — штатный режим.** Заполняем поля, для которых есть данные; остальные оставляем пустыми и перечисляем агенту. Придуманных и «ближайших похожих» значений в форме не бывает.
15. **Импорт вперёд публикации.** Внутри фазы сначала закрывается импортная часть, потом публикация. Сломанная публикация не блокирует импорт.
16. **Лента не вытесняет ядро.** Индекс и лента — фазы 9 и 10, после закрытого главного цикла. Исключение одно: накопление истории цен можно и нужно начинать раньше, потому что задним числом её не получить.
17. **Индекс не звонит и не создаёт объектов.** Он справочный. Любая автоматическая связь с собственником запрещена так же, как автоотправка формы.
18. **Три языка обязательны: грузинский, английский, русский.** Равноправны, все три с первого дня. Ни одной пользовательской строки в коде. `text-transform: uppercase` запрещён — у грузинского нет заглавных букв. Шрифт обязан покрывать мхедрули. Решение владельца, `ADR-0008-i18n.md`.

## Архитектурные инварианты

- `Property` ≠ `SourceListing`: у одного объекта может быть несколько объявлений на разных площадках.
- Статусы воронки — сущность `PipelineStatus` в БД, привязанная к компании. Хардкод статусов запрещён.
- `ActivityLog` пишется с первого дня — основа аналитики, KPI и будущей геймификации.
- Расширение ходит только через HTTPS API, никогда в БД напрямую.
- Логика источника живёт только в адаптере; core о конкретных сайтах не знает.
- У источника две независимые способности: чтение объявления (`parserVersion`) и заполнение формы (`formVersion`). Ломаются они по отдельности и версионируются отдельно.
- **Области проверок разные, и путать их нельзя.** Дубль при «Согласен» — область **команда** (конкуренция между командами разрешена владельцем). Самоимпорт своего объявления, предупреждение «объект уже размещён», исключение телефонов `PublishProfile`, порог «телефон у 5+ объектов» — область **компания**. Изоляция арендаторов — компания, жёстко.
- Состояние обзвона живёт на объявлении (`ObservationState`, привязано к команде), не на объекте. Воронка `Property` начинается с «В базе».
- Индекс объявлений общий для всех компаний, включая контакты: там только то, что площадка отдаёт по клику. Состояние работы — на команду и границу компании не покидает.
- **Лента выгодных объявлений видна всей компании**, всем командам и агентам. Объявление уходит из неё, как только любой агент компании отметил «Согласен». Фильтры агента — удобство просмотра, а не право доступа.
- Выгодность считается автоматически: отклонение цены за м² от медианы по корзине «район + комнатность + площадь». Мало объявлений в корзине — цифра не показывается вовсе.
- Телефон собственника — ключ дедупликации уровней 2 и 3. Объект без телефона ломает дедупликацию, поэтому импорт без него не проходит молча (правило 11).
- Опубликованное компанией объявление при обратном импорте привязывается к существующему `Property`, а не создаёт новый. Телефоны профилей публикации исключены из дедупликации по телефону.

## Стек

Подтверждён `ADR-0001-stack.md` 2026-08-31:

Next.js (App Router) + React + TypeScript (strict) · Tailwind · PostgreSQL · Prisma · Chrome Manifest V3 · pnpm workspaces.

API — route handlers Next.js, **вся доменная логика в `packages/core`**, который о HTTP не знает ничего. Именно так обеспечено правило 5: сценарию неоткуда взять `companyId`, кроме контекста.

Два места пишутся сырым SQL и в ORM не выражаются: поиск кандидатов на дубли и медиана по корзине для ленты. Между приложением и базой **обязателен пулер соединений** — без него serverless + Prisma исчерпает пул на первом же агентстве.

## Команды

Заполнено по факту фазы 2. Подробности запуска с нуля — `README.md`.

```bash
pnpm dev                # веб-приложение, http://localhost:3000
pnpm typecheck
pnpm lint               # eslint + проверка форматирования
pnpm format             # применить форматирование
pnpm test               # база не нужна
pnpm test:integration   # нужна живая база
pnpm build
```

```bash
pnpm db:up              # PostgreSQL в Docker
pnpm db:down
pnpm db:generate        # клиент Prisma
pnpm db:migrate         # применить миграции
pnpm db:studio
```

`pnpm db:seed` появится в фазе 3 вместе с сущностями: сеять пока нечего.

Команды идут через `scripts/with-env.mjs` — он подаёт единый корневой `.env`
инструментам, которые ищут его в разных местах. Поэтому `next` и `prisma`
запускаются через `pnpm`, а не напрямую.

## Стиль работы

- Маленькие коммиты, Conventional Commits (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`).
- Минимальные диффы: не рефактори то, что не входит в задачу.
- Новая зависимость — только с обоснованием в отчёте.
- Не больше 5 вопросов за раз, каждый с вариантом по умолчанию.
- Отчёт в конце шага: сделано / файлы / проверки / решения / новые OPEN / риски / следующий шаг.
